## Agent skills

### Issue tracker

Issues live in this repo's GitHub Issues (github.com/dhague/enchiridion), via the `gh` CLI. See `docs/agents/issue-tracker.md`.

**`gh` CLI hygiene:** Always use `gh <entity> view <n> --json title,body` (not bare `gh <entity> view`) — plain output hits a pager and GraphQL deprecation warnings can swallow results. Fetch multiple issues chained with `;` instead of `&&`. Don't grep files with guessed term spellings before reading them; use `Read` first.

### Domain docs

Single-context — one `CONTEXT.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Project: the wiki-knowledge plugin

This repo builds a Claude Code **wiki-knowledge plugin** (clean-room ingestion + retrieval over a git-backed markdown vault). Key resources, in order of authority:

- **`CONTEXT.md`** — domain glossary (page, kind, vault, typed edge, volatility, deployment mode, …). Read for vocabulary before writing anything that names a domain concept.
- **`docs/adr/`** — architectural decisions with rationale: no MCP server (0001), no embeddings/agent-read retrieval (0002), attribution from ingested content not git identity (0003), the two deployment modes + vault-root resolution order (0004), TDD-for-scripts/evals-for-agents (0005), stdlib SQLite FTS5 instead of embeddings (0006, strengthens rather than reopens 0002), turn cost not tool-call count (0007), plural kind-folders/singular kind-values (0008), one vault-relative `page_ref` spelling (0009), per-root `SearchIndex` cache not a caller-side memo (0010), Go rewrite scope/sequencing/toolchain (0011), Go port relaxes the byte-identical frontmatter round-trip contract (0012), Go binary lazy-fetched by a dependency-free bootstrap (0013), TypeScript rewrite on an approved interpreter to clear Windows Defender ASR (0017). Read before assuming *why* something is built the way it is.
- **`wiki-plugin/skills/wiki-conventions/SKILL.md`** — authoritative frontmatter schema, folder structure, relative-markdown link rules, and typed-edge vocabulary (`refines`/`contradicts`/`example-of`/`source`/`related`). Typed edges and `supersedes` are each one YAML key per relation, holding a list of clickable relative-markdown links. The raw-artifact pointer is `raw_source:` (a single markdown link, title = filename) — distinct from the `source` edge key. Also authoritative on link encoding (see below).
- **`docs/architecture.md`** — Mermaid diagrams of the script layer (package dependency graph, clustered by responsibility) and the skill→agent→cluster flow. A point-in-time snapshot, not kept in sync automatically — trust the code over the diagram if they disagree. Its boxes are named for the TypeScript modules under `enchiridion-ts/src/`.
- **`docs/TS-port.md`** — a summary of the TypeScript rewrite of the script layer: why it replaced the Go binary (ADR-0017), the ticket sequence (#255–#267), and where each module landed. A companion narrative to the ADRs and the architecture diagram, not a spec.
- **GitHub issues** — the wayfinder map [#1](https://github.com/dhague/enchiridion/issues/1) tracks phases as child tickets, with *Decisions so far* / *Not yet specified* / *Out of scope* sections. Check the map before assuming how something works — it's updated far more often than this file.
- **`README.md`** — project-level overview (install, design principles, commands, vault structure). Public-facing and derivative — not authoritative. When it disagrees with any of the docs above, the above win.
- **The enchiridion-vault** — ask it via `/wiki-retrieval <question>` (or the `wiki-researcher` agent) rather than reconstructing context by re-reading this file and grepping the tracker. It holds the *narrative* the other docs don't: why a decision went the way it did, what was tried and abandoned. It's ingestion output, not a spec — when it disagrees with `CONTEXT.md`, the ADRs, the conventions spec, or the tracker, those win. See the dogfooding-vault notes below for its location and the mandatory `WIKI_ROOT=` invocation rule.

If you're tempted to write a new standalone design doc for this project, don't — extend one of the docs above instead, so there's never a second version of the truth to keep in sync.

### Standing conventions

- **Terminology: the wiki's units are "pages", not "notes."** Standardized in `CONTEXT.md` and the conventions spec. "Note" may still appear in old ticket prose — same thing.
- **Folder structure is plugin-fixed and kind-axed**: `wiki/{concepts,entities,sources,synthesis}/` plus a user-extensible `raw/` inbox. Folders pluralize; kind *values* stay singular ([ADR-0008](docs/adr/0008-kind-folders-plural-kind-values-singular.md)). Don't reinvent it.
- **Raw filenames are preserved forever; link destinations are percent-encoded, not the filenames.** A file with external identity (came from outside the plugin) keeps its name verbatim, forever; a file the plugin creates carries a `YYYY-MM-DD-hhmm-` prefix bound at creation. Encoding lives at a single decode boundary in `enchiridion-ts/src/wikipage.ts`'s link machinery (minimal charset: `%`, space, `()`, `#`, `<>`; unicode stays literal), so destination-vs-path comparison stays correct by construction.
- **Model assignment** is a standing convention, not re-litigated per ticket: deterministic work is an `enchiridion` subcommand (no model), comprehension (map-reading, link-following) is Haiku, judgment (semantic chunking, dedup, edge-typing, conflict resolution) is Sonnet. Start at the floor for any new capability and escalate only on a measured failure.
- **The plugin lives at `wiki-plugin/`** (repo root). Its `name` is `wiki-knowledge` (in `.claude-plugin/plugin.json`) — deliberately different from the directory name. Everything under `wiki-plugin/` is implementation, not documentation — don't treat its README or code comments as a substitute for `CONTEXT.md`/`docs/adr/`/the conventions spec.
- **Git hygiene:** the repo sits inside a Resilio Sync folder, so `git status` routinely shows Resilio temp files (`*.rsls`) and a `.claude/worktrees/` dir — never stage these; add paths explicitly, not `git add -A`. The repo's `temp/` dir is scratch space, **not** gitignored — don't stage it unless asked.
- **Git branches and worktrees:** The remote branch `main` is protected — direct pushes are rejected, confirmed when a `v0.8.0` version-bump push to `main` bounced ([PR #197](https://github.com/dhague/enchiridion/pull/197)). Every change goes through a branch and a pull request, solo repo or not: create a worktree for each task, and when the work is ready, push the related branch to the remote and open a pull request. Wait for the user to confirm the PR is merged before cleaning up the branch/worktree.
- **Release process:** To cut a new release: (1) bump `wiki-plugin/.claude-plugin/plugin.json` version in a worktree → PR → wait for merge confirmation; (2) done — CI takes it from there. **Do NOT manually tag or run `gh release create`.** `tag-release.yml` fires on the `plugin.json` path change and creates/pushes the annotated tag (skips if the tag already exists). The Go release pipeline that used to consume that tag is **retired** (#267): `enchiridion-go/` is deleted, `go-enchiridion.yml` is a stripped no-op placeholder, and a TS-bundle release workflow (how a distributable plugin ships the esbuild bundle + wasm sidecar) is a separate ticket — a pushed tag currently triggers nothing. Also update the "Plugin version" line in *Current state* below.

### Script layer

**The script layer is a single TypeScript implementation at `enchiridion-ts/`, the completed port** ([ADR-0017](docs/adr/0017-typescript-rewrite-approved-interpreter-asr.md), #244/#252): the Go static binary it replaced tripped Windows Defender ASR rule `01443614` on corporate-managed machines, and the fix is a full, all-or-nothing port to TypeScript bundled by esbuild and run on an already-installed, already-trusted interpreter (Node, and Bun for OpenCode) — not a partial/strangler migration, since a locally-built Go `.exe` trips the same rule. The port landed module-by-module per #252's dependency-ordered sequence; it reached full parity and passed CI on both runtimes, and `enchiridion-go/` was deleted in #267 — one implementation, not two. **`wiki-plugin/bin/enchiridion` is a thin POSIX-sh shim** (#254) that execs `node` against `enchiridion-ts/dist/cli.cjs` (esbuild's bundled output, sibling directory), forwarding every argument; `ENCHIRIDION_BIN` still overrides it entirely for local dev. This retires [ADR-0013](docs/adr/0013-go-binary-lazy-fetch-dependency-free-bootstrap.md)'s lazy-fetch/PATH-preference bootstrap from the runtime path — `node` itself is the already-installed, already-trusted interpreter this rewrite exists to run inside of. All 14 subcommands below are implemented and exercised by CI on both runtimes.

**The script layer** is one `enchiridion` executable, one subcommand per capability, implemented in TypeScript under `enchiridion-ts/src/`. `wiki-plugin/scripts/` holds **only OpenCode install-time tooling** (`generate-opencode.py`, `install-opencode.py` — standalone, stdlib + `ruamel.yaml`, run once by a person to wire the plugin into an OpenCode vault, never by a skill or agent). If you are looking for a capability, it is a subcommand: `search`, `init`, `ingest`, `discover`, `ingest-scan`, `watch`, `save-session`, `tool-call-stats`, `commit`, `superseded-by`, `vault`, `page`, `place`, and `hook`.

**How `vault`, `page`, and `place` are spelled** (deliberate, not incidental): `enchiridion vault` — bare, or `vault root`, prints the resolved root; `vault move <old_ref> <new_ref>` moves a page and fixes every link, inbound and outbound. `enchiridion page get|set|merge <file> <key> …` is the frontmatter trio (`page`, not `frontmatter` — `page` is the domain noun in `CONTEXT.md`). `enchiridion place <kind> "<title>"` computes a new page's vault-relative path. `page` and `place` take only what you hand them and **resolve no vault root**; `vault` is the one that does, which is exactly why moving a page lives there — it needs every other page's text to rewrite inbound links.

**The hooks are subcommands too** — `hooks.json` calls `bin/enchiridion hook session-start` / `hook post-tool-use` (`enchiridion-ts/src/hooks.ts`, dispatched by `enchiridion-ts/src/cli.ts`), each reading its payload on stdin. Hooks run unattended, so they **fail open**: the subcommand swallows every handler error and exits 0, and `hooks.json` appends `|| exit 0` so an error degrades one session's side effect instead of blocking session start. Pre-#254, PostToolUse additionally set `ENCHIRIDION_NO_FETCH=1` because it fires on every tool call and a failing lazy-fetch retried there would cost two curls per call, all session, unread; now that `bin/enchiridion` is a shim with no fetch step (see the Script layer section above), that env var is gone from `hooks.json` — it had nothing left to gate.

**Module inventory** (`enchiridion-ts/src/`): `wikipage.ts` (the pure page model — `Get`/`Set`/`Merge`/`Retarget`/`PlanMove`, no I/O), `vault.ts` (the `Vault` I/O type plus `ResolveRoot`), `place.ts` (kebab-slug + kind-folder path computation; `KindFolders` is the single source of truth for the mapping), `pagerecord.ts` (sole reader of the frontmatter schema — derives `kind` from folder and `superseded_by` by inverting `supersedes` edges), `vaultgit.ts` (all git access, via isomorphic-git), `chainofevidence.ts` (the page→stub→raw-file rule, run by `ingest` as pre-flight *and* commit-time gate), `commit.ts` (structured git commit per manifest, [ADR-0003](docs/adr/0003-attribution-from-content-not-git-identity.md)), `ingest.ts` (the `IngestPlan` executor), `searchindex.ts` (FTS5), `discover.ts`, `supersededby.ts`, `ingestscan.ts` + `ingestignore.ts`, `watch.ts`, `sessionstate.ts` + `transcriptcapture.ts`, `toolcallstats.ts`, `initwiki.ts`, `hooks.ts`, and `cli.ts` (one subcommand per file). The `vault -> wikipage` one-way dependency survived the port. `Vault.Pages()` is the one page-enumeration interface (`rel` always vault-relative, `raw/` never walked).

**Three port consequences worth knowing before editing.** First, **the `Vault` has no search-index facade** — `searchindex` does not import `vault` at all: it depends on `vaultgit` (blobs, dates) and computes `Status()`'s on-disk-vs-indexed count itself by counting `wiki/**.md` on disk ([ADR-0015](docs/adr/0015-search-index-view-of-committed-history.md); `searchindex`'s centre of gravity is `vaultgit`), so proxying back through `vault` would be an import cycle. Second, **`enchiridion ingest` prints the post-commit tool-call cost summary** by reading a hook-written log; it is best-effort and silent when no log exists, keeping the SHA the first line of stdout either way. Third, **nothing self-heals the #114 kind-folder migration** — the migration script is deleted (every known vault is migrated). What survives is the *check*: `Vault.LegacyKindFolders` detects an unmigrated vault and `ingest` refuses outright, spelling out the `git mv`. Silence was the one option ruled out — `place.Path` resolves canonical kinds from `KindFolders`, so ingesting into an unmigrated vault (one restored from an old backup, say) would split one kind across `wiki/concept/` and `wiki/concepts/`.

**Text search** is SQLite FTS5, zero new runtime dependencies ([ADR-0006](docs/adr/0006-stdlib-fts5-not-embeddings.md)) — `enchiridion-ts/src/searchindex.ts` over `node-sqlite3-wasm` (a bundled wasm build, so no system SQLite and no FTS5 capability probe; and hence no `re` fallback backend; `backend` survives in `--status` only as an output contract). A gitignored `.wiki-knowledge/index.db` (never committed; no WAL, since Resilio + SQLite sidecars corrupts) holds page metadata + an FTS5 table over title/summary/body. **The index is a materialised view of `HEAD`'s `wiki/` tree, not of the working tree** ([ADR-0015](docs/adr/0015-search-index-view-of-committed-history.md), which supersedes ADR-0006's mtime-scan mechanism on this point): `meta.git_head` holds the last `HEAD` the index has accounted for, and every search compares it to the repository's current `HEAD` via `VaultGit.CommittedPages` — content is read from **git blobs**, never from files on disk, so a page sitting uncommitted in the working tree is structurally invisible to search, not filtered by policy. `HEAD == watermark` is free (one commit lookup, no filesystem work); otherwise the range back to the watermark is walked and only the changed `wiki/**.md` paths are re-read from `HEAD`'s tree, or, if the watermark isn't reachable (amend, rebase, `reset --hard`, a re-clone over an existing `index.db`), the index drops and rebuilds from `HEAD`'s tree — reachability is answered by that same walk, not a separate query. `search --status` reports `git_head` plus a count of `wiki/**.md` files on disk exceeding the indexed page count, the one diagnostic that still walks the filesystem (never on the search hot path). Query tokenization phrase-quotes by default (a bare hyphenated tag is a syntax error to raw FTS5 `MATCH`); `--raw` is the escape hatch. `index.db` is the sole read path: the FTS index is the *filter* that narrows a vault to candidates the summary-first frontier then works over. `SchemaVersion` is `"4"`, using the `porter unicode61` tokenizer and `0.0,10.0,5.0,1.0` bm25 weights. Migration on a version bump is still delete-and-rebuild, never in-place — `--reindex` re-points to this model too: bare `--reindex` forces the range walk to `HEAD`, `--reindex --full` forces a full tree read regardless of the current watermark. **The port has no `ForRoot` and wants none** (ADR-0010's *Go port* section, carried across): `Open`/`Close` make the lifetime explicit, so the one-connection-at-a-time constraint is held structurally — the CLI command opens the single handle and passes it down, and everything beneath it (`discover.Check`/`discover.Discover`) takes a `Searcher`, never a root, so it can't open a competing connection.

**One contract a future edit must not break** (property-tested in `enchiridion-ts/src/wikipage.test.ts` via `fast-check`): a page **move touches only link lines and all links still resolve** — including frontmatter markdown links (typed edges, `supersedes`, `raw_source`), spliced by the same whole-document rule as body links. Frontmatter round-trip is not byte-identical by design (it does preserve key *order*; the measured divergence is scalar quote style alone) — see [ADR-0012](docs/adr/0012-go-frontmatter-round-trip-relaxed.md).

**Dev setup / running tests (TypeScript):** `package.json`'s `engines.node` is `>=22.12.0` (commander 15's own floor); run from `enchiridion-ts/` — `npm ci`, then `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build` (esbuild bundle to `dist/cli.cjs` + the `node-sqlite3-wasm` `.wasm` sidecar), `npm test` (Node's built-in test runner via `tsx`) and `npm run test:bun` (needs `bun` on PATH). CI (`ts-enchiridion.yml`) runs this matrix on both Node.js LTS and Bun; both must pass. No Go toolchain is required anywhere — there is no `enchiridion-go/` anymore. `wiki-plugin/bin/enchiridion`'s shim behaviour (exec `node`/`$ENCHIRIDION_BIN` against the bundle, args forwarded) is covered by `wiki-plugin/tests/bin_enchiridion.bats` — needs `bats` (`brew install bats-core`); run `bats wiki-plugin/tests/bin_enchiridion.bats` from the repo root. Note `bin/enchiridion` no longer does the ADR-0014 PATH-preference/version-drift check the old Go-era bats suite covered — that logic lived in the lazy-fetch bootstrap ADR-0017 retires from the runtime path. For the OpenCode install tooling only, `wiki-plugin/.venv` (gitignored) holds `ruamel.yaml` + `pytest` installed directly — not `pip install -e .` (no package-discovery config, editable install fails); run `<venv python> -m pytest` from `wiki-plugin/`.

### Current state

- **Ingestion, retrieval, and auto-ingest are all built**, not just specced. [#11](https://github.com/dhague/enchiridion/issues/11) is the closed roll-up spec for `wiki-ingest` (Sonnet) and `wiki-researcher` (Haiku).
  - **Ingestion:** `wiki-ingest` authors an `IngestPlan` JSON document, executed atomically by `enchiridion ingest` (place → frontmatter → body → manifest → commit; two-phase pre-flight validation; the plan is resolved once so validate and execute can't diverge, #125; no rollback, writes are idempotent so rerun-after-fix is safe). This is the production entrypoint the `wiki-ingest` skill shells out to.
  - **Auto-ingest** ([#37](https://github.com/dhague/enchiridion/issues/37), closed): `/wiki-watch` — a user-run, foreground, event-driven watcher (`enchiridion watch`), not a daemon or hook — Ctrl-C to stop. Dispatches one `wiki-ingest` subagent per queued file via `enchiridion ingest-scan`.
  - **Retrieval:** `agents/wiki-researcher.md` (Haiku) + `skills/wiki-retrieval/SKILL.md` — query expansion → FTS5 search → frontmatter-first frontier → budget bound (~2 hops, ~12 pages) → edge-following (question-shape → typed edge + direction) → supersession/volatility-aware ranking (recency is never a re-ranking signal except for explicitly time-anchored questions, and even then a `supersedes` edge wins) → synthesis with honest temporal framing, and a confirmed synthesis-page save. Design finding worth carrying: **a subagent cannot ask for the confirmation that gates a write**, so `wiki-researcher` *proposes* a `save-candidate` block and the invoking session performs the save on explicit yes (`Write` is removed from its tools). The save reuses `enchiridion ingest` (`action: synthesize`, same shape as ingestion but `kind: synthesis`, no raw artifact).
- **Remaining per the wayfinder map ([#1](https://github.com/dhague/enchiridion/issues/1)):** the OpenCode port ([#90](https://github.com/dhague/enchiridion/issues/90)–[#94](https://github.com/dhague/enchiridion/issues/94)) is **closed** — host-neutral SKILL.md files, `generate-opencode.py`/`install-opencode.py`, an OpenCode session-tracker plugin, a `/save-conversation` port, and CI wiring are all done. Statusline and evals ([#47](https://github.com/dhague/enchiridion/issues/47), below) remain. `wiki-doctor` ([#74](https://github.com/dhague/enchiridion/issues/74)–[#79](https://github.com/dhague/enchiridion/issues/79)) is still at the design-question stage, not yet scoped into build tickets.
- **The script layer is a TypeScript bundle** (`enchiridion`, one subcommand per capability), esbuild's `enchiridion-ts/dist/cli.cjs` + the `node-sqlite3-wasm` `.wasm` sidecar, invoked through the `wiki-plugin/bin/enchiridion` shim on an already-installed interpreter (Node; Bun for OpenCode) — see [ADR-0017](docs/adr/0017-typescript-rewrite-approved-interpreter-asr.md). The Go binary ([ADR-0011](docs/adr/0011-go-rewrite-scope-sequencing-toolchain.md)/[0012](docs/adr/0012-go-frontmatter-round-trip-relaxed.md)/[0013](docs/adr/0013-go-binary-lazy-fetch-dependency-free-bootstrap.md)) is gone, so **code signing ([#154](https://github.com/dhague/enchiridion/issues/154)) is moot** — there is no own-built PE to sign, and the runtime payload is code the interpreter runs, not an executable the OS gates. **`enchiridion save-session` serves both hosts**, detecting the host from which session-id variable is set — Claude Code's `$CLAUDE_CODE_SESSION_ID` (hook-recorded transcript path on disk) or OpenCode's `$OPENCODE_SESSION_ID` (tracker-plugin state, transcript fetched by shelling out to `opencode export`, whose stdout goes to a temp *file* because it truncates on a pipe). Both vars can be set at once (one host run from the other's shell), and env alone can't say which is innermost, so the tie breaks on evidence: OpenCode wins only when its tracker plugin recorded *that* id in *this* project, else Claude Code. Everything downstream of the host-specific fetch — turn filtering, rendering, filename binding — is the one shared seam in `enchiridion-ts/src/transcriptcapture.ts`, so an OpenCode capture inherits its generic "Source: Claude Code session transcript" line.
- **`/to-spec` needs a scope-clarifying question first** on this repo — it's wayfinder-mapped (phases charted as child tickets off #1), not "one undiscussed feature per invocation," so expect to ask which phase(s) before drafting.
- **Eval strategy:** the hand-authored "golden vault" is shelved in favor of a small synthetic fixture — the irreducible deliverable is the **property list**, not the pages. ~8 pages of deliberately fake content at `wiki-plugin/evals/fixtures/` plus `evals/PROPERTIES.md` (human-owned, agent-drafted, [ADR-0005](docs/adr/0005-tdd-for-scripts-evals-for-agents.md)). Tracked at [#47](https://github.com/dhague/enchiridion/issues/47), still open. The live dogfooding vault stays complementary, never the substrate — it's 100% ingestion output and it moves. The eval **harness** (headless `claude -p` runs, pass-rate, structural assertions, LLM judge for fuzzy questions) is still fog, graduates once #47 lands.

### The dogfooding vault

- **Live vault at `$WIKI_ROOT`** — a separate git repo (own `wiki/`/`raw/`, own history), not part of this one. Runs `wiki-knowledge` in query-from-anywhere mode, registered via a local-directory marketplace in its own `.claude/settings.json`. This is real usage, not a fixture — treat anything found working in it as a genuine bug report, not a hand-run to reproduce and discard.
- **Always invoke scripts as `WIKI_ROOT=<vault root> <path to script>` when touching vault files.** `$WIKI_ROOT` is the highest-priority rule in the vault-root resolution order ([ADR-0004](docs/adr/0004-deployment-modes-and-vault-root-resolution.md)); everything else guesses from `cwd`. That guess is actively wrong from this repo: `enchiridion/` has no `wiki/` or `.wiki-root` marker, so resolution falls through to "`cwd` is the vault root" and a script will happily write pages into the source tree instead of the vault. Set it per-invocation, not exported, so each command stays self-describing about which vault it hit.
- **This vault is long-term memory.** Instead of reconstructing context every session (read CLAUDE.md, grep the tracker), look things up via `wiki-retrieval`. Every significant conversation gets saved and ingested.
- **`/save-conversation`** finds its own session's transcript via a `SessionStart` hook (`wiki-plugin/hooks/hooks.json` + `enchiridion hook session-start`, recording `transcript_path` per `session_id` under `.claude/wiki-knowledge/sessions/<session_id>.json`) and names the raw file from an **agent-authored slug, not the transcript's `ai-title`** (which names how a session opened, not what it became). Filename: `raw/conversations/<YYYY-MM-DD-hhmm>-<agent-slug>-<short-uuid>.md`, sanitized (`[^a-z0-9]+`→`-`). The name is bound once at first save — a re-save globs `*-<short_id>.md` and rewrites that file in place, on the principle that a topic change should start a new session.
