## Agent skills

### Issue tracker

Issues live in this repo's GitHub Issues (github.com/dhague/enchiridion), using the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

Canonical five-role vocabulary, each label string equal to its role name. See `docs/agents/triage-labels.md`. **Not all five exist yet in the tracker** — `docs/agents/triage-labels.md` documents the mapping as if the labels are already created, but as of 2026-07-19 only `ready-for-agent` exists (created ad hoc when first needed). Before applying `needs-triage`, `needs-info`, or `ready-for-human`, check `gh label list` and create the label first if missing.

### Domain docs

Single-context — one `CONTEXT.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Project: the wiki-knowledge plugin

This repo builds a Claude Code **wiki-knowledge plugin** (clean-room ingestion + retrieval over a git-backed markdown vault). Key resources:

- **`CONTEXT.md`** — the domain glossary (page, kind, vault, typed edge, volatility, deployment mode, …). Read this for vocabulary before writing anything that names a domain concept.
- **`docs/adr/`** — architectural decisions with their rationale: no MCP server (0001), no embeddings/agent-read retrieval (0002), attribution from ingested content not git identity (0003), the two deployment modes + vault-root resolution order (0004), TDD-for-scripts/evals-for-agents (0005), and stdlib SQLite FTS5 instead of embeddings (0006 — deliberately framed as *strengthening* 0002's no-embeddings stance rather than reopening it). Read these before assuming *why* something is built the way it is.
- **`wiki-plugin/skills/wiki-conventions/SKILL.md`** — the authoritative **frontmatter schema, folder structure, relative-markdown link rules, and typed-edge vocabulary** (`refines`/`contradicts`/`example-of`/`source`/`related`). Written in #6. Non-obvious shape (a post-resolution amendment — see the [#6](https://github.com/dhague/enchiridion/issues/6) comments): typed edges **and** `supersedes` are each **one YAML key per relation, holding a list of clickable relative-markdown links**; the raw-artifact pointer is **`raw_source:`** (a single markdown link, title = filename) — renamed from `source:` so it can't collide with the `source` edge key. Also authoritative on link encoding since [#38](https://github.com/dhague/enchiridion/issues/38) (see below).
- **GitHub issues** — the wayfinder map [Wiki Knowledge Plugin (#1)](https://github.com/dhague/enchiridion/issues/1) tracks phases as child tickets; each resolution is recorded in the map's *Decisions so far*, and *Not yet specified* / *Out of scope* track remaining and deferred work (including the old plan's §12 roadmap items). Before assuming how something works, check the map first — it is updated far more often than this file.
- **The enchiridion-vault** — ask it via `/wiki-retrieval <question>` (or the `wiki-researcher` agent) rather than reconstructing context by re-reading this file and grepping the tracker. Every significant session is saved and ingested there, so it holds the *narrative* the other four resources don't: why a decision went the way it did, what was tried and abandoned, what a hand-run actually surfaced. It's the fastest first stop for "what did we decide about X?" — but it's ingestion output, not a spec, so when it disagrees with `CONTEXT.md`, the ADRs, the conventions spec, or the tracker, those win. See the dogfooding-vault bullets below for its location and the mandatory `WIKI_ROOT=` invocation rule.

If you're tempted to write a new standalone design doc for this project, don't — extend one of the four docs above instead, so there's never a second version of the truth to keep in sync.

- **Terminology: the wiki's units are "pages", not "notes".** Firm preference, standardized in `CONTEXT.md` and the conventions spec (#6). "Note" may still appear in old ticket prose — same thing.
- **Folder structure is plugin-fixed and kind-axed** (`wiki/{concept,entity,source,synthesis}/` + a user-extensible `raw/` inbox), decided in #5. Don't reinvent it.
- **Raw filenames are preserved forever; link destinations are percent-encoded, not the filenames.** Decided in [#28](https://github.com/dhague/enchiridion/issues/28), built in [#38](https://github.com/dhague/enchiridion/issues/38): a file with external identity (came from outside the plugin) keeps its name verbatim, forever — a file the plugin creates carries a `YYYY-MM-DD-hhmm-` prefix bound **at creation**, not guessed later from mtime. `normalize_raw.py` (the old after-the-fact renamer) is **deleted**. Encoding lives at a single decode boundary in `wikipage.py`'s link machinery (minimal charset: `%`, space, `()`, `#`, `<>`; unicode stays literal) so the destination-vs-path comparison stays correct by construction. [#43](https://github.com/dhague/enchiridion/issues/43) (widen `LinkMatch` with a label span so moves could relabel `raw_source` links) was ruled out of scope once #38 landed — nothing needs a label span when raw files are never renamed.
- **Model assignment is a standing convention, not re-litigated per ticket:** deterministic work is a Python script (no model), comprehension (map-reading, link-following) is Haiku, judgment (semantic chunking, dedup, edge-typing, conflict resolution) is Sonnet. Start at the floor for any new capability and escalate only on a measured failure — see #11 for the current ingestion/retrieval assignment.
- **The plugin lives at `wiki-plugin/`** (repo root), scaffolded in #3. The plugin **`name` is `wiki-knowledge`** (in `.claude-plugin/plugin.json`) — deliberately different from the `wiki-plugin/` directory name. **Everything under `wiki-plugin/` is implementation, not documentation** — don't treat its README or code comments as a substitute for `CONTEXT.md`/`docs/adr/`/the conventions spec.
- **The deterministic script layer is built around one `WikiPage`/`Vault` library, split across two modules.** `wiki-plugin/scripts/wikipage.py` holds the pure half — `WikiPage` (`get`/`set`/`merge`/`retarget`, each returning a new instance) plus `plan_move`, no I/O at all; `wiki-plugin/scripts/vault.py` holds `Vault`, which owns all I/O (`load`/`write`/`load_wiki_pages`/`set`/`merge`/`move_page`/`rewrite_inbound_links`/`pages()`/`search()`/`reindex()`) alongside `resolve_vault_root()`. The dependency runs **one way, `vault -> wikipage`, with no deferred import on either side** — importing `Vault` from `wikipage` is the old shape and no longer works. That split dissolved a real `wikipage ↔ search_index` import cycle (page_record imported wikipage back), which used to force deferred imports in both modules and only misfired when `wikipage.py` was run as a *script*; the subprocess CLI tests in `tests/test_wikipage.py` and `tests/test_vault.py` are the regression guard. **The tests split on the same seam as the modules:** `test_wikipage.py` is pure — no test in it touches a vault — and every `Vault` test lives in `test_vault.py`. **The CLIs split on the same seam:** `wikipage.py get/set/merge` each take a *file path* and do pure text work, so none resolves a vault root; **moving a page is `vault.py move <old_rel> <new_rel>`** (it needs the whole vault to fix inbound links), and bare `vault.py` still prints the resolved root as `wiki-retrieval`'s SKILL.md expects. Current `wiki-plugin/scripts/` inventory: `vault.py` + `wikipage.py` (the library above), `page_record.py` ([#40](https://github.com/dhague/enchiridion/issues/40) — the **one** module that reads the frontmatter schema; derives `kind` from folder and `superseded_by` by inverting `supersedes` edges), `build_index.py` (now a pure renderer over `page_record.load_records()`), `place.py` (kebab-slug + kind-folder path computation, [prose→script push](https://github.com/dhague/enchiridion/commit/20e7865)), `commit.py` (structured git commit per manifest — [ADR-0003](docs/adr/0003-attribution-from-content-not-git-identity.md)), `search_index.py` + `search.py` ([#39](https://github.com/dhague/enchiridion/issues/39) — SQLite FTS5 text search, see below), `ingest.py` ([#49](https://github.com/dhague/enchiridion/issues/49) — the `IngestPlan` executor, see below), `session_state.py` + `save-session-to-vault.py` (conversation capture, see below), and `init_wiki.py` ([#wiki-init](wiki-plugin/skills/wiki-init/SKILL.md) vault scaffolding). `normalize_raw.py` is gone (#38, above). `Vault.pages()` ([#41](https://github.com/dhague/enchiridion/issues/41)) is the one page-enumeration interface (`rel` always vault-relative, `_index.md` never a page, `raw/` never walked) — a 2026-07-28 architecture review's refactor cluster (#40-#45).
  - **Text search is stdlib SQLite FTS5, zero new dependencies** ([#36](https://github.com/dhague/enchiridion/issues/36) research → [#39](https://github.com/dhague/enchiridion/issues/39) build, [ADR-0006](docs/adr/0006-stdlib-fts5-not-embeddings.md)). A gitignored `.wiki-knowledge/index.db` (never committed — 15 MB of binary churn per ingestion; no WAL, since Resilio + SQLite sidecars corrupts) holds page metadata + an FTS5 table over title/summary/body. Correctness lives in an unconditional `(mtime_ns, size)` staleness scan on **every** search (measured 53 ms at 2000 pages), not in `Vault.write`'s inline update (a latency optimisation only) — so the index can't be wrong because a caller forgot to call the right method. `tokenize_query()` phrase-quotes by default (a bare hyphenated tag like `wiki-knowledge` is a syntax error to raw FTS5 `MATCH`); `--raw` is the escape hatch. `_index.md` still exists and is still read whole (the *map*); the FTS index is the *filter* that narrows a big vault down to what the map-read works over.
  - **Dev setup / running tests:** deps live in `wiki-plugin/.venv` (gitignored), installed **directly** (`ruamel.yaml markdown-it-py pytest hypothesis`) — **not** `pip install -e .` (no package-discovery config, so editable install fails). Run the suite from `wiki-plugin/`: `<venv python> -m pytest`. `pyproject.toml` sets `pythonpath = ["scripts"]`. Suite size has been climbing steadily (88 → 254 passing as of 2026-07-28, across #32/#39/#40/#41/#45/#49/#51) — treat a big drop in count as a signal something regressed, not just noise.
  - **Two contracts a future edit must not break** (both property-tested, now living in `wikipage.py`): a no-op frontmatter `set` round-trips **byte-identical** (only the frontmatter block is ever re-serialised; ruamel pinned to `indent(mapping=2, sequence=4, offset=2)` so the spec's 2-space edge-list indentation survives), and a page **move touches only link lines and all links still resolve** — including frontmatter markdown links (typed edges, `supersedes`, `raw_source`), which splice by the same whole-document rule as body links.
- **Git hygiene:** the repo sits inside a Resilio Sync folder, so `git status` routinely shows Resilio temp files (`*.rsls`) and a `.claude/worktrees/` dir — **never stage these**; add paths explicitly rather than `git add -A`. The repo's `temp/` dir is scratch space (handoff docs, etc.) and is **not** gitignored — don't stage it unless asked. Commits go to `main` (solo repo); the harness will branch-first when asked to commit, then merge/delete on request.
- **Phase 3 (ingestion) and Phase 5 (retrieval) are both now built, not just specced.** [#11](https://github.com/dhague/enchiridion/issues/11) is the `ready-for-agent` spec for both `wiki-ingest` (Sonnet) and `wiki-researcher` (Haiku) — read it first for scope/acceptance shape.
  - **Ingestion:** single-doc happy path (#14) and relate-to-existing-vault dedup/edges/contradiction (#15) landed first (both closed). The orchestration has since been mechanized further: [#42](https://github.com/dhague/enchiridion/issues/42)/[#49](https://github.com/dhague/enchiridion/issues/49) collapse `wiki-ingest`'s 12-call orchestration behind one agent-authored `IngestPlan` JSON document, executed atomically by a new `ingest.py` (place → frontmatter → body → index → manifest → commit, with two-phase pre-flight validation and no rollback — writes are idempotent so a rerun-after-fix is safe). **This is merged to `main`** (`5ce09ed` via `b2a79df`) and is the real production entrypoint the `wiki-ingest` skill shells out to. It landed broken, though, and the repair is worth knowing about: #49 and #38 were built on parallel branches and merged without reconciliation, so `ingest.py` still imported the deleted `normalize_raw` — every invocation died with `ModuleNotFoundError` and `pytest` couldn't even collect. [#51](https://github.com/dhague/enchiridion/issues/51) (closed, `2e0b10b`) removed the rename/retarget path and fixed a second instance of the same gap: validation compared the *encoded* link destination against paths on disk, which only worked while raw filenames were being sanitized. **The moral generalizes — when two branches touch the same seam, reconcile at merge time; neither branch's own tests catch it.** [#21](https://github.com/dhague/enchiridion/issues/21) (per-chunk body-writing for multi-idea documents) is re-pointed at the plan's `body` field and blocked by #49. [#19](https://github.com/dhague/enchiridion/issues/19) (fixture hand-run) is rescoped and blocked by #47 (eval fixture, below). Still open and unblocked: [#34](https://github.com/dhague/enchiridion/issues/34) (mandatory `source/` stub + source edge for every ingested raw file, gated in `commit.py`), [#26](https://github.com/dhague/enchiridion/issues/26) (ingestion control, a grilling ticket), [#13](https://github.com/dhague/enchiridion/issues/13) (`INGESTION.md` in raw folders), [#37](https://github.com/dhague/enchiridion/issues/37) (auto-ingest new files as they appear).
  - **Retrieval:** [#16](https://github.com/dhague/enchiridion/issues/16) built `agents/wiki-researcher.md` (Haiku) + `skills/wiki-retrieval/SKILL.md` — query expansion → search → frontmatter-first frontier → budget bound (~2 hops, ~12 pages) → synthesis with honest temporal framing. [#17](https://github.com/dhague/enchiridion/issues/17), now merged to `main`, added edge-following (question-shape → typed edge + direction) and supersession/volatility-aware ranking (same-set supersession collapses chains to their head; recency is never a re-ranking signal except for explicitly time-anchored questions, and even then a `supersedes` edge wins) — rebased cleanly onto #39's single FTS5-search-call retrieval step. Open: [#18](https://github.com/dhague/enchiridion/issues/18) (confirmed synthesis-page save — the agent already has `Write`, reserved but unused until this lands).
- **This project's tickets don't map 1:1 onto `/to-spec`'s default assumption of "one undiscussed feature per invocation."** It's wayfinder-mapped (phases charted as child tickets off #1), so when `/to-spec` is invoked without an explicit feature already established in conversation, expect to need a scope-clarifying question (which phase(s)?) before drafting — confirmed acceptable in [#11](https://github.com/dhague/enchiridion/issues/11)'s drafting session rather than skipped.
- **Eval strategy: the hand-authored "golden vault" is shelved; a small synthetic fixture takes its place.** [#7](https://github.com/dhague/enchiridion/issues/7) settled it — hand-authoring 15-30 pages of real knowledge to buy an eval substrate is a Catch-22 (that's what the plugin exists to remove), so the irreducible deliverable is the **property list**, not the pages. Replacement: ~8 pages of deliberately fake content at `wiki-plugin/evals/fixtures/` (a genuine vault root, `wiki/`+`raw/` siblings) plus `evals/PROPERTIES.md`, a human-owned table the agent drafts and the human signs off on ([ADR-0005](docs/adr/0005-tdd-for-scripts-evals-for-agents.md), amended). Implementation tracked at [#47](https://github.com/dhague/enchiridion/issues/47), still open. The **live dogfooding vault stays complementary, never the substrate** — it's 100% ingestion output and it moves, but its hand-runs (#16, #17) have already surfaced real rules no fixture would have imagined. The eval **harness** itself (headless `claude -p` runs, pass-rate, structural assertions, LLM judge only for fuzzy questions) is still fog — not yet specified, graduates once #47 lands.
- **There's a live dogfooding vault at $WIKI_ROOT$** — a separate git repo (own `wiki/`/`raw/`, own history), not part of this one. It runs `wiki-knowledge` in query-from-anywhere mode: registered via a local-directory marketplace in its own `.claude/settings.json` (`extraKnownMarketplaces` + `enabledPlugins` — see that vault's README for the exact shape). This is real usage, not a fixture — treat anything found by working in it (like [#22](https://github.com/dhague/enchiridion/issues/22)'s `scripts/` path-portability gap, or #31's stale marketplace path) as a genuine bug report, not a hand-run to reproduce and discard.
  - **Always invoke the scripts as `WIKI_ROOT=<vault root> <path to script>` when touching vault files.** `$WIKI_ROOT` is the highest-priority rule in `vault.py`'s resolution order and wins unconditionally ([ADR-0004](docs/adr/0004-deployment-modes-and-vault-root-resolution.md)); everything else is a guess from `cwd`. The guess is actively wrong when working from this repo: `enchiridion/` has no `wiki/` or `.wiki-root` marker in it or any ancestor, so resolution falls through to "`cwd` is the vault root" and a script will happily write pages into the *source tree* instead of the vault. Setting it per-invocation rather than exporting it keeps each command self-describing about which vault it hit — worth it in a session that touches both repos.
- **This dogfooding vault is my long-term memory.** Instead of having to reconstruct context every session (read CLAUDE.md, grep the issue tracker, etc), you can look things up in the vault instead via `wiki-retrieval`. Every significant conversation we have gets saved into the vault and ingested.
- **`/save-conversation` finds its own session's transcript via a `SessionStart` hook** ([#23](https://github.com/dhague/enchiridion/issues/23), closed), and names the raw file from an **agent-authored slug, not the transcript's own `ai-title`**. `wiki-plugin/hooks/hooks.json` + `hooks/store_transcript_path.py` record `transcript_path` per `session_id` (gitignored, under the project's `.claude/wiki-knowledge/sessions/<session_id>.json`) via `scripts/session_state.py`; `scripts/save-session-to-vault.py` looks itself up by `$CLAUDE_CODE_SESSION_ID`. Filename scheme, decided in [#33](https://github.com/dhague/enchiridion/issues/33): `raw/conversations/<YYYY-MM-DD-hhmm>-<agent-slug>-<short-uuid>.md` — `ai-title` was measured and rejected (it's derived from the session's *first* prompt, so it names how a session opened, not what it became); the agent instead passes its own slug, sanitized (`[^a-z0-9]+`→`-`) since it's untrusted filesystem input. The name is **bound once at first save**: a re-save globs `*-<short_id>.md` and rewrites that same file in place, so no rename (and no inbound-link rewrite) is ever triggered — the accepted cost is a slug fixed at first save, on the standing principle that a session is single-topic and a topic change is the signal to start a new session. [#45](https://github.com/dhague/enchiridion/issues/45) (closed, merged to `main` as `ec15908`) split the script at a pure seam (`transcript_to_page`) for testability and fixed a real cwd-sensitive bug in `session_state.sessions_dir()`. [#46](https://github.com/dhague/enchiridion/issues/46) (open) implements the agent-authored-slug filename change itself.
- **A Python LSP MCP server is configured for the plugin's dev work** ([#30](https://github.com/dhague/enchiridion/issues/30)/[#29](https://github.com/dhague/enchiridion/issues/29)) — `mcp__python-lsp__*` tools (find_definition/find_references/find_symbols) are available for navigating `wiki-plugin/scripts/`.
- **Sandcastle (sandboxed dev to cut permission prompts) was investigated and ruled out** ([#24](https://github.com/dhague/enchiridion/issues/24), closed) — it only suppresses prompts inside its own single-repo container (fatal given the dogfooding vault is a second committing repo), and is an AFK orchestrator, not an interactive-session tool. Findings + a ready-to-paste native `permissions.allow`/`deny`/`additionalDirectories` config are in the ticket's resolution comment if the prompt noise is worth addressing another way.
- **First tagged release: `v0.2.0`** (plugin.json bumped from the untagged `0.1.0` scaffold), covering everything through #23 — script layer, conventions spec, and the ingestion pipeline's single-doc + relate-to-existing-vault happy paths. **No newer tag exists yet**, despite a substantial amount landing since (the WikiPage/Vault rebuild, FTS5 search, retrieval, the #40-45 refactor cluster) — there's still no established version-bump/release cadence, so don't assume `main` at any given moment matches the latest release.
