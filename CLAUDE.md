### Issue tracker

Issues live in this repo's GitHub Issues (github.com/dhague/enchiridion), via the `gh` CLI. See `docs/agents/issue-tracker.md`.

**`gh` CLI hygiene:** Always use `gh <entity> view <n> --json title,body` (not bare `gh <entity> view`) — plain output hits a pager and GraphQL deprecation warnings can swallow results. Fetch multiple issues chained with `;` instead of `&&`. Don't grep files with guessed term spellings before reading them; use `Read` first.

## Project: the wiki-knowledge plugin

This repo builds a Claude Code **wiki-knowledge plugin** (clean-room ingestion + retrieval over a git-backed markdown vault). Key resources, in order of authority:

- **`CONTEXT.md`** — domain glossary (page, kind, vault, typed edge, volatility, deployment mode, …). Read for vocabulary before writing anything that names a domain concept.
- **`docs/adr/`** — architectural decisions with rationale: no MCP server (0001), no embeddings/agent-read retrieval (0002), attribution from ingested content not git identity (0003), the two deployment modes + vault-root resolution order (0004), TDD-for-scripts/evals-for-agents (0005), stdlib SQLite FTS5 instead of embeddings (0006, strengthens rather than reopens 0002), turn cost not tool-call count (0007), plural kind-folders/singular kind-values (0008), one vault-relative `page_ref` spelling (0009), per-root `SearchIndex` cache not a caller-side memo (0010), Go rewrite scope/sequencing/toolchain (0011), Go port relaxes the byte-identical frontmatter round-trip contract (0012), Go binary lazy-fetched by a dependency-free bootstrap (0013). Read before assuming *why* something is built the way it is.
- **`wiki-plugin/skills/wiki-conventions/SKILL.md`** — authoritative frontmatter schema, folder structure, relative-markdown link rules, and typed-edge vocabulary (`refines`/`contradicts`/`example-of`/`source`/`related`). Typed edges and `supersedes` are each one YAML key per relation, holding a list of clickable relative-markdown links. The raw-artifact pointer is `raw_source:` (a single markdown link, title = filename) — distinct from the `source` edge key. Also authoritative on link encoding (see below).
- **`docs/architecture.md`** — Mermaid diagrams of the Python codebase (module dependency graph, clustered by responsibility) and the skill→agent→script flow. A point-in-time snapshot, not kept in sync automatically — trust the code over the diagram if they disagree.
- **GitHub issues** — the wayfinder map [#1](https://github.com/dhague/enchiridion/issues/1) tracks phases as child tickets, with *Decisions so far* / *Not yet specified* / *Out of scope* sections. Check the map before assuming how something works — it's updated far more often than this file.
- **`README.md`** — project-level overview (install, design principles, commands, vault structure). Public-facing and derivative — not authoritative. When it disagrees with any of the docs above, the above win.
- **The enchiridion-vault** — ask it via `/wiki-retrieval <question>` (or the `wiki-researcher` agent) rather than reconstructing context by re-reading this file and grepping the tracker. It holds the *narrative* the other docs don't: why a decision went the way it did, what was tried and abandoned. It's ingestion output, not a spec — when it disagrees with `CONTEXT.md`, the ADRs, the conventions spec, or the tracker, those win. See the dogfooding-vault notes below for its location and the mandatory `WIKI_ROOT=` invocation rule.

If you're tempted to write a new standalone design doc for this project, don't — extend one of the docs above instead, so there's never a second version of the truth to keep in sync.

### Standing conventions

- **Terminology: the wiki's units are "pages", not "notes."** Standardized in `CONTEXT.md` and the conventions spec. "Note" may still appear in old ticket prose — same thing.
- **Folder structure is plugin-fixed and kind-axed**: `wiki/{concepts,entities,sources,synthesis}/` plus a user-extensible `raw/` inbox. Folders pluralize; kind *values* stay singular ([ADR-0008](docs/adr/0008-kind-folders-plural-kind-values-singular.md)). Don't reinvent it.
- **Raw filenames are preserved forever; link destinations are percent-encoded, not the filenames.** A file with external identity (came from outside the plugin) keeps its name verbatim, forever; a file the plugin creates carries a `YYYY-MM-DD-hhmm-` prefix bound at creation. Encoding lives at a single decode boundary in `wikipage.py`'s link machinery (minimal charset: `%`, space, `()`, `#`, `<>`; unicode stays literal), so destination-vs-path comparison stays correct by construction.
- **Model assignment** is a standing convention, not re-litigated per ticket: deterministic work is a Python script (no model), comprehension (map-reading, link-following) is Haiku, judgment (semantic chunking, dedup, edge-typing, conflict resolution) is Sonnet. Start at the floor for any new capability and escalate only on a measured failure.
- **The plugin lives at `wiki-plugin/`** (repo root). Its `name` is `wiki-knowledge` (in `.claude-plugin/plugin.json`) — deliberately different from the directory name. Everything under `wiki-plugin/` is implementation, not documentation — don't treat its README or code comments as a substitute for `CONTEXT.md`/`docs/adr/`/the conventions spec.
- **Git hygiene:** the repo sits inside a Resilio Sync folder, so `git status` routinely shows Resilio temp files (`*.rsls`) and a `.claude/worktrees/` dir — never stage these; add paths explicitly, not `git add -A`. The repo's `temp/` dir is scratch space, **not** gitignored — don't stage it unless asked. Commits go to `main` (solo repo); the harness branches first when asked to commit, then merges/deletes on request.
- **Git branches and worktrees:** The remote branch `main` is protected. Create a worktree for each task, and when completed push the related branch to the remote and open a pull request.

### Script layer

Built around one `WikiPage`/`Vault` library, split across two modules with a one-way dependency (`vault -> wikipage`, no deferred imports either side):

- `wiki-plugin/scripts/wikipage.py` — the pure half. `WikiPage` (`get`/`set`/`merge`/`retarget`, each returning a new instance) plus `plan_move`. No I/O.
- `wiki-plugin/scripts/vault.py` — `Vault`, owning all I/O (`load`/`write`/`load_wiki_pages`/`set`/`merge`/`move_page`/`rewrite_inbound_links`/`pages()`/`pages_with_text()`/`search()`/`reindex()`) plus `resolve_vault_root()`.

Tests and CLIs split on the same seam: `test_wikipage.py` is pure (no vault touched); every `Vault` test lives in `test_vault.py`. `wikipage.py get/set/merge` take a file path and never resolve a vault root; moving a page is `vault.py move <old_ref> <new_ref>` (needs the whole vault to fix inbound links); bare `vault.py` prints the resolved root.

Rest of `wiki-plugin/scripts/` inventory: `page_record.py` (sole reader of the frontmatter schema; derives `kind` from folder and `superseded_by` by inverting `supersedes` edges), `place.py` (kebab-slug + kind-folder path computation), `vault_git.py` (sole git-shell-out module — every `shutil.which("git")`/`subprocess.run(["git", ...])` lives here, absent-git policy stated once at the `VaultGit` interface: a strict surface raising `GitError` for `commit.py`/`init_wiki.py`, a lenient surface returning `None`/`False`/`{}` for `ingest_scan.py`/`search_index.py`; callers inject it so tests run against an in-memory fake, see `tests/fake_vault_git.py`), `commit.py` (structured git commit per manifest, [ADR-0003](docs/adr/0003-attribution-from-content-not-git-identity.md)), `chain_of_evidence.py` (the page→stub→raw-file rule shared by `ingest.py`'s pre-flight check and `commit.py`'s hard gate — every raw file producing pages must also produce a `wiki/sources/` stub, with a `source` edge back to it from every page it produced), `search_index.py` + `search.py` (SQLite FTS5 text search, see below), `discover.py` (single-call overlap-candidate + tag-vocabulary lookup off a draft `IngestPlan`, fronting `Vault.search`, so wiki-ingest's dedup step is deterministic, not re-derived from prose), `ingest.py` (the `IngestPlan` executor, see below), `ingest_scan.py` (the `raw/` sweep: offers a file when no page's `raw_source` points at it, or the pointing page is stale; per-folder `.ingestignore`, no ancestor walk), `watch_raw.py` (event-driven `raw/` watcher behind `/wiki-watch` — debounce, lock file, queue file — foreground, not a daemon), `session_state.py` + `transcript_capture.py` (JSONL-to-page rendering plus filesystem-local session lookup/write; the reusable capability behind `/save-conversation`) + `save-session-to-vault.py` (thin CLI adapter over it, see below), `init_wiki.py` (vault scaffolding, see `skills/wiki-init/SKILL.md`), `migrate_kind_folders_0114.py` (one-off singular→plural kind-folder migration per ADR-0008, self-healing via `Vault.__init__` — delete both together once no unmigrated vault remains), `tool_call_stats.py` (summarizes a session's hook-logged tool calls; cost/prompt-count visibility, not a turn count — [ADR-0007](docs/adr/0007-turn-cost-not-tool-call-count.md)). `Vault.pages()` is the one page-enumeration interface (`rel` always vault-relative, `raw/` never walked).

**Text search** is stdlib SQLite FTS5, zero new dependencies ([ADR-0006](docs/adr/0006-stdlib-fts5-not-embeddings.md)). A gitignored `.wiki-knowledge/index.db` (never committed; no WAL, since Resilio + SQLite sidecars corrupts) holds page metadata + an FTS5 table over title/summary/body. Correctness lives in an unconditional `(mtime_ns, size)` staleness scan on every search (~53ms at 2000 pages), not in `Vault.write`'s inline update — so the index can't be wrong because a caller forgot to call the right method. `tokenize_query()` phrase-quotes by default (a bare hyphenated tag is a syntax error to raw FTS5 `MATCH`); `--raw` is the escape hatch. `search.py`/`index.db` is the sole read path: the FTS index is the *filter* that narrows a vault to candidates the summary-first frontier then works over. `search_index.for_root()` is the per-root cache of the one-`SearchIndex`-per-process contract ([ADR-0010](docs/adr/0010-search-index-per-root-cache.md)) — call it instead of constructing `SearchIndex` directly whenever a root may already have a live connection.

**Dev setup / running tests:** deps live in `wiki-plugin/.venv` (gitignored), installed directly (`ruamel.yaml markdown-it-py pytest hypothesis`) — not `pip install -e .` (no package-discovery config, editable install fails). Run from `wiki-plugin/`: `<venv python> -m pytest`. `pyproject.toml` sets `pythonpath = ["scripts"]`. `pyrightconfig.json` enforces strong typing in default (non-strict) mode over `scripts`/`tests` — keep new code typed enough to pass it.

**Two contracts a future edit must not break** (both property-tested, in `wikipage.py`): a no-op frontmatter `set` round-trips byte-identical (only the frontmatter block is re-serialised; ruamel pinned to `indent(mapping=2, sequence=4, offset=2)`), and a page **move touches only link lines and all links still resolve** — including frontmatter markdown links (typed edges, `supersedes`, `raw_source`), spliced by the same whole-document rule as body links.

### Current state

- **Ingestion, retrieval, and auto-ingest are all built**, not just specced. [#11](https://github.com/dhague/enchiridion/issues/11) is the closed roll-up spec for `wiki-ingest` (Sonnet) and `wiki-researcher` (Haiku).
  - **Ingestion:** `wiki-ingest` authors an `IngestPlan` JSON document, executed atomically by `ingest.py` (place → frontmatter → body → manifest → commit; two-phase pre-flight validation; the plan is resolved once so validate and execute can't diverge, #125; no rollback, writes are idempotent so rerun-after-fix is safe). This is the production entrypoint the `wiki-ingest` skill shells out to.
  - **Auto-ingest** ([#37](https://github.com/dhague/enchiridion/issues/37), closed): `/wiki-watch` — a user-run, foreground, event-driven watcher (`watch_raw.py`), not a daemon or hook — Ctrl-C to stop. Dispatches one `wiki-ingest` subagent per queued file via `ingest_scan.py`.
  - **Retrieval:** `agents/wiki-researcher.md` (Haiku) + `skills/wiki-retrieval/SKILL.md` — query expansion → FTS5 search → frontmatter-first frontier → budget bound (~2 hops, ~12 pages) → edge-following (question-shape → typed edge + direction) → supersession/volatility-aware ranking (recency is never a re-ranking signal except for explicitly time-anchored questions, and even then a `supersedes` edge wins) → synthesis with honest temporal framing, and a confirmed synthesis-page save. Design finding worth carrying: **a subagent cannot ask for the confirmation that gates a write**, so `wiki-researcher` *proposes* a `save-candidate` block and the invoking session performs the save on explicit yes (`Write` is removed from its tools). The save reuses `ingest.py` (`action: synthesize`, same shape as ingestion but `kind: synthesis`, no raw artifact).
- **Remaining per the wayfinder map ([#1](https://github.com/dhague/enchiridion/issues/1)):** the OpenCode port ([#90](https://github.com/dhague/enchiridion/issues/90)–[#94](https://github.com/dhague/enchiridion/issues/94), all open — host-neutral SKILL.md files, `generate-opencode.py`/`install-opencode.py`, an OpenCode session-tracker plugin, a `/save-conversation` port, CI wiring), statusline, and evals ([#47](https://github.com/dhague/enchiridion/issues/47), below). `wiki-doctor` ([#74](https://github.com/dhague/enchiridion/issues/74)–[#79](https://github.com/dhague/enchiridion/issues/79)) is still at the design-question stage, not yet scoped into build tickets.
- **Go rewrite** ([#140](https://github.com/dhague/enchiridion/issues/140), design settled, build not started — blocked on the OpenCode port above finishing first): the Python script layer becomes a single static Go binary (`enchiridion`, one subcommand per current script), distributed per-platform via GitHub Releases and lazy-fetched by a dependency-free bootstrap, so the plugin needs no Python installed — see [ADR-0011](docs/adr/0011-go-rewrite-scope-sequencing-toolchain.md)/[0012](docs/adr/0012-go-frontmatter-round-trip-relaxed.md)/[0013](docs/adr/0013-go-binary-lazy-fetch-dependency-free-bootstrap.md). Child tickets: [#149](https://github.com/dhague/enchiridion/issues/149) (scaffolding/CI/bootstrap) → [#150](https://github.com/dhague/enchiridion/issues/150) (`search`/`init`) → [#151](https://github.com/dhague/enchiridion/issues/151) (`ingest` + contracts) → [#152](https://github.com/dhague/enchiridion/issues/152) (remaining subcommands) → [#153](https://github.com/dhague/enchiridion/issues/153) (hooks); [#154](https://github.com/dhague/enchiridion/issues/154) (code signing) deferred.

### The dogfooding vault

- **Live vault at `$WIKI_ROOT`** — a separate git repo (own `wiki/`/`raw/`, own history), not part of this one. Runs `wiki-knowledge` in query-from-anywhere mode, registered via a local-directory marketplace in its own `.claude/settings.json`. This is real usage, not a fixture — treat anything found working in it as a genuine bug report, not a hand-run to reproduce and discard.
- **Always invoke scripts as `WIKI_ROOT=<vault root> <path to script>` when touching vault files.** `$WIKI_ROOT` is the highest-priority rule in `vault.py`'s resolution order ([ADR-0004](docs/adr/0004-deployment-modes-and-vault-root-resolution.md)); everything else guesses from `cwd`. That guess is actively wrong from this repo: `enchiridion/` has no `wiki/` or `.wiki-root` marker, so resolution falls through to "`cwd` is the vault root" and a script will happily write pages into the source tree instead of the vault. Set it per-invocation, not exported, so each command stays self-describing about which vault it hit.
- **This vault is long-term memory.** Instead of reconstructing context every session (read CLAUDE.md, grep the tracker), look things up via `wiki-retrieval`. Every significant conversation gets saved and ingested.
- **`/save-conversation`** finds its own session's transcript via a `SessionStart` hook (`wiki-plugin/hooks/hooks.json` + `hooks/store_transcript_path.py`, recording `transcript_path` per `session_id` under `.claude/wiki-knowledge/sessions/<session_id>.json`) and names the raw file from an **agent-authored slug, not the transcript's `ai-title`** (which names how a session opened, not what it became). Filename: `raw/conversations/<YYYY-MM-DD-hhmm>-<agent-slug>-<short-uuid>.md`, sanitized (`[^a-z0-9]+`→`-`). The name is bound once at first save — a re-save globs `*-<short_id>.md` and rewrites that file in place, on the principle that a topic change should start a new session.
