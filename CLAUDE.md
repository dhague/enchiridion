## Project: the wiki-knowledge plugin

This repo builds a Claude Code **wiki-knowledge plugin** (clean-room ingestion + retrieval over a git-backed markdown vault). Key resources, in order of authority:

- **`CONTEXT.md`** — domain glossary (page, kind, vault, typed edge, volatility, deployment mode, …). Read for vocabulary before writing anything that names a domain concept.
- **`docs/adr/`** — architectural decisions with rationale: no MCP server (0001), no embeddings/agent-read retrieval (0002), attribution from ingested content not git identity (0003), the two deployment modes + vault-root resolution order (0004), TDD-for-scripts/evals-for-agents (0005), stdlib SQLite FTS5 instead of embeddings (0006, strengthens rather than reopens 0002), turn cost not tool-call count (0007), plural kind-folders/singular kind-values (0008), one vault-relative `page_ref` spelling (0009), per-root `SearchIndex` cache not a caller-side memo (0010), Go rewrite scope/sequencing/toolchain (0011), Go port relaxes the byte-identical frontmatter round-trip contract (0012), Go binary lazy-fetched by a dependency-free bootstrap (0013). Read before assuming *why* something is built the way it is.
- **`wiki-plugin/skills/wiki-conventions/SKILL.md`** — authoritative frontmatter schema, folder structure, relative-markdown link rules, and typed-edge vocabulary (`refines`/`contradicts`/`example-of`/`source`/`related`). Typed edges and `supersedes` are each one YAML key per relation, holding a list of clickable relative-markdown links. The raw-artifact pointer is `raw_source:` (a single markdown link, title = filename) — distinct from the `source` edge key. Also authoritative on link encoding (see below).
- **`docs/architecture.md`** — Mermaid diagrams of the script layer (package dependency graph, clustered by responsibility) and the skill→agent→cluster flow. A point-in-time snapshot, not kept in sync automatically — trust the code over the diagram if they disagree. Its boxes are named for the Go packages under `enchiridion-go/internal/`.
- **GitHub issues** — the wayfinder map [#1](https://github.com/dhague/enchiridion/issues/1) tracks phases as child tickets, with *Decisions so far* / *Not yet specified* / *Out of scope* sections. Check the map before assuming how something works — it's updated far more often than this file.
- **`README.md`** — project-level overview (install, design principles, commands, vault structure). Public-facing and derivative — not authoritative. When it disagrees with any of the docs above, the above win.
- **The enchiridion-vault** — ask it via `/wiki-retrieval <question>` (or the `wiki-researcher` agent) rather than reconstructing context by re-reading this file and grepping the tracker. It holds the *narrative* the other docs don't: why a decision went the way it did, what was tried and abandoned. It's ingestion output, not a spec — when it disagrees with `CONTEXT.md`, the ADRs, the conventions spec, or the tracker, those win. See the dogfooding-vault notes below for its location and the mandatory `WIKI_ROOT=` invocation rule.

If you're tempted to write a new standalone design doc for this project, don't — extend one of the docs above instead, so there's never a second version of the truth to keep in sync.

### Standing conventions

- **Terminology: the wiki's units are "pages", not "notes."** Standardized in `CONTEXT.md` and the conventions spec. "Note" may still appear in old ticket prose — same thing.
- **Folder structure is plugin-fixed and kind-axed**: `wiki/{concepts,entities,sources,synthesis}/` plus a user-extensible `raw/` inbox. Folders pluralize; kind *values* stay singular ([ADR-0008](docs/adr/0008-kind-folders-plural-kind-values-singular.md)). Don't reinvent it.
- **Raw filenames are preserved forever; link destinations are percent-encoded, not the filenames.** A file with external identity (came from outside the plugin) keeps its name verbatim, forever; a file the plugin creates carries a `YYYY-MM-DD-hhmm-` prefix bound at creation. Encoding lives at a single decode boundary in `internal/wikipage`'s link machinery (minimal charset: `%`, space, `()`, `#`, `<>`; unicode stays literal), so destination-vs-path comparison stays correct by construction.
- **Model assignment** is a standing convention, not re-litigated per ticket: deterministic work is an `enchiridion` subcommand (no model), comprehension (map-reading, link-following) is Haiku, judgment (semantic chunking, dedup, edge-typing, conflict resolution) is Sonnet. Start at the floor for any new capability and escalate only on a measured failure.
- **The plugin lives at `wiki-plugin/`** (repo root). Its `name` is `wiki-knowledge` (in `.claude-plugin/plugin.json`) — deliberately different from the directory name. Everything under `wiki-plugin/` is implementation, not documentation — don't treat its README or code comments as a substitute for `CONTEXT.md`/`docs/adr/`/the conventions spec.
- **Git hygiene:** the repo sits inside a Resilio Sync folder, so `git status` routinely shows Resilio temp files (`*.rsls`) and a `.claude/worktrees/` dir — never stage these; add paths explicitly, not `git add -A`. The repo's `temp/` dir is scratch space, **not** gitignored — don't stage it unless asked.
- **Git branches and worktrees:** The remote branch `main` is protected — direct pushes are rejected, confirmed when a `v0.8.0` version-bump push to `main` bounced ([PR #197](https://github.com/dhague/enchiridion/pull/197)). Every change goes through a branch and a pull request, solo repo or not: create a worktree for each task, and when the work is ready, push the related branch to the remote and open a pull request. Wait for the user to confirm the PR is merged before cleaning up the branch/worktree.

### Script layer

**The script layer is Go, end to end.** Per [ADR-0011](docs/adr/0011-go-rewrite-scope-sequencing-toolchain.md), it is a single static binary at `enchiridion-go/` (`enchiridion`, one subcommand per capability), invoked through `wiki-plugin/bin/enchiridion` — a POSIX-sh entrypoint that lazy-fetches the release binary ([ADR-0013](docs/adr/0013-go-binary-lazy-fetch-dependency-free-bootstrap.md)); `ENCHIRIDION_BIN` points it at a local `go build` instead. `wiki-plugin/scripts/` holds **only OpenCode install-time tooling** (`generate-opencode.py`, `install-opencode.py` — standalone, stdlib + `ruamel.yaml`, run once by a person to wire the plugin into an OpenCode vault, never by a skill or agent). If you are looking for a capability, it is a subcommand: `search`, `init`, `ingest`, `discover`, `ingest-scan`, `watch`, `save-session`, `tool-call-stats`, `commit`, `superseded-by`, `vault`, `page`, `place`, and `hook`.

**How `vault`, `page`, and `place` are spelled** (deliberate, not incidental): `enchiridion vault` — bare, or `vault root`, prints the resolved root; `vault move <old_ref> <new_ref>` moves a page and fixes every link, inbound and outbound. `enchiridion page get|set|merge <file> <key> …` is the frontmatter trio (`page`, not `frontmatter` — `page` is the domain noun in `CONTEXT.md`). `enchiridion place <kind> "<title>"` computes a new page's vault-relative path. `page` and `place` take only what you hand them and **resolve no vault root**; `vault` is the one that does, which is exactly why moving a page lives there — it needs every other page's text to rewrite inbound links.

**The hooks are Go too** — `hooks.json` calls `bin/enchiridion hook session-start` / `hook post-tool-use` (`internal/hooks`, dispatched by `internal/cli/hook.go`), each reading its payload on stdin. Hooks run unattended, so they **fail open**: the subcommand swallows every handler error and exits 0, and `hooks.json` appends `|| exit 0` so a failed lazy binary fetch degrades one session's side effect instead of blocking session start. PostToolUse additionally sets `ENCHIRIDION_NO_FETCH=1` (honoured by both bootstraps: use the cached binary, never download) — it fires on every tool call, so retrying a failing fetch there would cost two curls per call, all session, unread; SessionStart is the one that warms the cache.

**Package inventory** (`enchiridion-go/internal/`): `wikipage` (the pure page model — `Get`/`Set`/`Merge`/`Retarget`/`PlanMove`, no I/O), `vault` (the `Vault` I/O type plus `ResolveRoot`), `place` (kebab-slug + kind-folder path computation; `KindFolders` is the single source of truth for the mapping), `pagerecord` (sole reader of the frontmatter schema — derives `kind` from folder and `superseded_by` by inverting `supersedes` edges), `vaultgit` (all git access, via embedded go-git), `chainofevidence` (the page→stub→raw-file rule, run by `ingest` as pre-flight *and* commit-time gate), `commit` (structured git commit per manifest, [ADR-0003](docs/adr/0003-attribution-from-content-not-git-identity.md)), `ingest` (the `IngestPlan` executor), `searchindex` (FTS5), `discover`, `supersededby`, `ingestscan` + `ingestignore`, `watch`, `sessionstate` + `transcriptcapture`, `toolcallstats`, `initwiki`, `hooks`, and `cli` (one file per subcommand). The `vault -> wikipage` one-way dependency survived the port. `Vault.Pages()` is the one page-enumeration interface (`rel` always vault-relative, `raw/` never walked).

**Three port consequences worth knowing before editing.** First, **Go's `Vault` has no search-index facade** — `searchindex` imports `vault`, so proxying back would be an import cycle; the inline index update was only ever a latency optimisation, since correctness lives in the staleness scan (ADR-0006). Second, **`enchiridion ingest` prints the post-commit tool-call cost summary** by reading a hook-written log; it is best-effort and silent when no log exists, keeping the SHA the first line of stdout either way. Third, **nothing self-heals the #114 kind-folder migration** — the migration script is deleted (every known vault is migrated). What survives is the *check*: `Vault.LegacyKindFolders` detects an unmigrated vault and `ingest` refuses outright, spelling out the `git mv`. Silence was the one option ruled out — `place.Path` resolves canonical kinds from `KindFolders`, so ingesting into an unmigrated vault (one restored from an old backup, say) would split one kind across `wiki/concept/` and `wiki/concepts/`.

**Text search** is SQLite FTS5, zero new runtime dependencies ([ADR-0006](docs/adr/0006-stdlib-fts5-not-embeddings.md)) — `internal/searchindex` over `ncruces/go-sqlite3` + its loadable `ext/fts5`, a pure-Go wasm build, so no system SQLite and no FTS5 capability probe (and hence no `re` fallback backend; `backend` survives in `--status` only as an output contract). A gitignored `.wiki-knowledge/index.db` (never committed; no WAL, since Resilio + SQLite sidecars corrupts) holds page metadata + an FTS5 table over title/summary/body. Correctness lives in an unconditional `(mtime_ns, size)` staleness scan on every search (~53ms at 2000 pages), not in an inline update on write — so the index can't be wrong because a caller forgot to call the right method. **[ADR-0015](docs/adr/0015-search-index-view-of-committed-history.md) replaces that mechanism** ([#176](https://github.com/dhague/enchiridion/issues/176) — decided, not yet implemented): the index becomes a view of committed history — a `HEAD`-SHA watermark in `meta`, content read from git blobs, no mtime scan and no `git status`, and uncommitted pages deliberately not searchable. Until that lands, the sentence above is what the code does; don't build on the mtime scan without checking which is live. Query tokenization phrase-quotes by default (a bare hyphenated tag is a syntax error to raw FTS5 `MATCH`); `--raw` is the escape hatch. `index.db` is the sole read path: the FTS index is the *filter* that narrows a vault to candidates the summary-first frontier then works over. `SchemaVersion` is `"3"` (`"4"` under ADR-0015), using the `porter unicode61` tokenizer and `0.0,10.0,5.0,1.0` bm25 weights. Migration on a version bump is still delete-and-rebuild, never in-place. **Go has no `ForRoot` and wants none** (ADR-0010's *Go port* section): `Open`/`Close` make the lifetime explicit, so the one-connection-at-a-time constraint is held structurally — the cobra command opens the single handle and passes it down, and everything beneath it (`discover.Check`/`discover.Discover`) takes a `Searcher`, never a root, so it can't open a competing connection.

**One contract a future edit must not break** (property-tested in `internal/wikipage` via `rapid`): a page **move touches only link lines and all links still resolve** — including frontmatter markdown links (typed edges, `supersedes`, `raw_source`), spliced by the same whole-document rule as body links. Frontmatter round-trip is not byte-identical by design (it does preserve key *order*; the measured divergence is scalar quote style alone) — see [ADR-0012](docs/adr/0012-go-frontmatter-round-trip-relaxed.md).

**Dev setup / running tests:** run from `enchiridion-go/` — `go test ./...`, `go vet ./...`, `gofmt -l .`; property tests use `pgregory.net/rapid` and markdown parsing uses `goldmark`. For the OpenCode install tooling only, `wiki-plugin/.venv` (gitignored) holds `ruamel.yaml` + `pytest` installed directly — not `pip install -e .` (no package-discovery config, editable install fails); run `<venv python> -m pytest` from `wiki-plugin/`.

### Current state

- **Ingestion, retrieval, and auto-ingest are all built**, not just specced. [#11](https://github.com/dhague/enchiridion/issues/11) is the closed roll-up spec for `wiki-ingest` (Sonnet) and `wiki-researcher` (Haiku).
  - **Ingestion:** `wiki-ingest` authors an `IngestPlan` JSON document, executed atomically by `enchiridion ingest` (place → frontmatter → body → manifest → commit; two-phase pre-flight validation; the plan is resolved once so validate and execute can't diverge, #125; no rollback, writes are idempotent so rerun-after-fix is safe). This is the production entrypoint the `wiki-ingest` skill shells out to.
  - **Auto-ingest** ([#37](https://github.com/dhague/enchiridion/issues/37), closed): `/wiki-watch` — a user-run, foreground, event-driven watcher (`enchiridion watch`), not a daemon or hook — Ctrl-C to stop. Dispatches one `wiki-ingest` subagent per queued file via `enchiridion ingest-scan`.
  - **Retrieval:** `agents/wiki-researcher.md` (Haiku) + `skills/wiki-retrieval/SKILL.md` — query expansion → FTS5 search → frontmatter-first frontier → budget bound (~2 hops, ~12 pages) → edge-following (question-shape → typed edge + direction) → supersession/volatility-aware ranking (recency is never a re-ranking signal except for explicitly time-anchored questions, and even then a `supersedes` edge wins) → synthesis with honest temporal framing, and a confirmed synthesis-page save. Design finding worth carrying: **a subagent cannot ask for the confirmation that gates a write**, so `wiki-researcher` *proposes* a `save-candidate` block and the invoking session performs the save on explicit yes (`Write` is removed from its tools). The save reuses `enchiridion ingest` (`action: synthesize`, same shape as ingestion but `kind: synthesis`, no raw artifact).
- **Remaining per the wayfinder map ([#1](https://github.com/dhague/enchiridion/issues/1)):** the OpenCode port ([#90](https://github.com/dhague/enchiridion/issues/90)–[#94](https://github.com/dhague/enchiridion/issues/94)) is **closed** — host-neutral SKILL.md files, `generate-opencode.py`/`install-opencode.py`, an OpenCode session-tracker plugin, a `/save-conversation` port, and CI wiring are all done. Statusline and evals ([#47](https://github.com/dhague/enchiridion/issues/47), below) remain. `wiki-doctor` ([#74](https://github.com/dhague/enchiridion/issues/74)–[#79](https://github.com/dhague/enchiridion/issues/79)) is still at the design-question stage, not yet scoped into build tickets.
- **The script layer is a single static Go binary** (`enchiridion`, one subcommand per capability), distributed per-platform via GitHub Releases and lazy-fetched by a dependency-free bootstrap — see [ADR-0011](docs/adr/0011-go-rewrite-scope-sequencing-toolchain.md)/[0012](docs/adr/0012-go-frontmatter-round-trip-relaxed.md)/[0013](docs/adr/0013-go-binary-lazy-fetch-dependency-free-bootstrap.md). Code signing ([#154](https://github.com/dhague/enchiridion/issues/154)) is deliberately deferred — its 2026-08-14 status check reaffirmed that (no reports of Gatekeeper/SmartScreen friction); revisit if that changes. **`enchiridion save-session` serves both hosts**, detecting the host from which session-id variable is set — Claude Code's `$CLAUDE_CODE_SESSION_ID` (hook-recorded transcript path on disk) or OpenCode's `$OPENCODE_SESSION_ID` (tracker-plugin state, transcript fetched by shelling out to `opencode export`, whose stdout goes to a temp *file* because it truncates on a pipe). Both vars can be set at once (one host run from the other's shell), and env alone can't say which is innermost, so the tie breaks on evidence: OpenCode wins only when its tracker plugin recorded *that* id in *this* project, else Claude Code. Everything downstream of the host-specific fetch — turn filtering, rendering, filename binding — is the one shared seam in `internal/transcriptcapture`, so an OpenCode capture inherits its generic "Source: Claude Code session transcript" line.
- **`/to-spec` needs a scope-clarifying question first** on this repo — it's wayfinder-mapped (phases charted as child tickets off #1), not "one undiscussed feature per invocation," so expect to ask which phase(s) before drafting.
- **Eval strategy:** the hand-authored "golden vault" is shelved in favor of a small synthetic fixture — the irreducible deliverable is the **property list**, not the pages. ~8 pages of deliberately fake content at `wiki-plugin/evals/fixtures/` plus `evals/PROPERTIES.md` (human-owned, agent-drafted, [ADR-0005](docs/adr/0005-tdd-for-scripts-evals-for-agents.md)). Tracked at [#47](https://github.com/dhague/enchiridion/issues/47), still open. The live dogfooding vault stays complementary, never the substrate — it's 100% ingestion output and it moves. The eval **harness** (headless `claude -p` runs, pass-rate, structural assertions, LLM judge for fuzzy questions) is still fog, graduates once #47 lands.
- **Plugin version: `0.8.0`** (`wiki-plugin/.claude-plugin/plugin.json`) — don't assume `main` at any given moment matches any given tag. This is also the version `bin/enchiridion` tries to fetch a binary for.

### The dogfooding vault

- **Live vault at `$WIKI_ROOT`** — a separate git repo (own `wiki/`/`raw/`, own history), not part of this one. Runs `wiki-knowledge` in query-from-anywhere mode, registered via a local-directory marketplace in its own `.claude/settings.json`. This is real usage, not a fixture — treat anything found working in it as a genuine bug report, not a hand-run to reproduce and discard.
- **Always invoke scripts as `WIKI_ROOT=<vault root> <path to script>` when touching vault files.** `$WIKI_ROOT` is the highest-priority rule in the vault-root resolution order ([ADR-0004](docs/adr/0004-deployment-modes-and-vault-root-resolution.md)); everything else guesses from `cwd`. That guess is actively wrong from this repo: `enchiridion/` has no `wiki/` or `.wiki-root` marker, so resolution falls through to "`cwd` is the vault root" and a script will happily write pages into the source tree instead of the vault. Set it per-invocation, not exported, so each command stays self-describing about which vault it hit.
- **This vault is long-term memory.** Instead of reconstructing context every session (read CLAUDE.md, grep the tracker), look things up via `wiki-retrieval`. Every significant conversation gets saved and ingested.
- **`/save-conversation`** finds its own session's transcript via a `SessionStart` hook (`wiki-plugin/hooks/hooks.json` + `enchiridion hook session-start`, recording `transcript_path` per `session_id` under `.claude/wiki-knowledge/sessions/<session_id>.json`) and names the raw file from an **agent-authored slug, not the transcript's `ai-title`** (which names how a session opened, not what it became). Filename: `raw/conversations/<YYYY-MM-DD-hhmm>-<agent-slug>-<short-uuid>.md`, sanitized (`[^a-z0-9]+`→`-`). The name is bound once at first save — a re-save globs `*-<short_id>.md` and rewrites that file in place, on the principle that a topic change should start a new session.
