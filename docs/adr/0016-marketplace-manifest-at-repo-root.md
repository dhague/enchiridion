# marketplace.json moves to repo root; plugin.json stays under wiki-plugin/

[#217](https://github.com/dhague/enchiridion/issues/217) wants `wiki-knowledge` installable via `/plugin marketplace add dhague/enchiridion` + `/plugin install wiki-knowledge`, with no `git clone` step. Claude Code's `owner/repo` shorthand only discovers a marketplace manifest at `.claude-plugin/marketplace.json` in the repo root — it does not walk subdirectories — so the manifest moves there from its previous home at `wiki-plugin/.claude-plugin/marketplace.json`. `plugin.json` itself does not move; it stays at `wiki-plugin/.claude-plugin/plugin.json`, and the marketplace entry's `source` field changes from `"./"` to `"./wiki-plugin"` to bridge the two locations. Both `${CLAUDE_PLUGIN_ROOT}` resolution and relative-path `source` resolution work identically for GitHub-shorthand installs once the manifest is at root, so this is the minimal change that satisfies the constraint — moving `wiki-plugin/` itself was considered and rejected, since nothing about the constraint requires the plugin's own directory to change.

`git clone` remains the documented path for contributors working on `enchiridion-go/` or the wiki-plugin source, demoted from the README's default install instructions to its Development section — the same "optional accelerator over an existing baseline" shape as [ADR-0014](0014-package-manager-distribution.md) used for the binary. The dogfooding vault's existing registration (`extraKnownMarketplaces` with a `directory`-source `settings.json` entry pointing straight at `wiki-plugin/`) is unaffected and left as-is; it's a different, already-working install path for a different audience.

## Consequences

The repo root now carries a `.claude-plugin/` manifest even though most of the root (`enchiridion-go/`, `docs/`, evals) isn't part of the plugin — this is a manifest file, not a code relocation, so it doesn't imply the plugin owns the repo root. If a second plugin is ever added to this repo, it's a second entry in the same root `marketplace.json`, not a second marketplace file.
