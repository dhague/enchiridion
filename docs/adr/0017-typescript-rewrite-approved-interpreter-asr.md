# Rewrite the script layer in TypeScript, run on an approved interpreter (Node/Bun), to clear Windows Defender ASR

[#244](https://github.com/dhague/enchiridion/issues/244) rewrites the Go script layer as a single bundled TypeScript/JavaScript file executed by an already-installed interpreter (Node, and Bun for the OpenCode host). This reverses [ADR-0011](0011-go-rewrite-scope-sequencing-toolchain.md)'s central goal — a zero-runtime-dependency static binary — because that goal collided head-on with Windows Defender Attack Surface Reduction (ASR) on the corporate-managed machines this plugin has to run on, and the collision is unwinnable while we ship an own-built executable.

## Context: the real blocker is ASR, not a generic "AV false positive"

On the target machines the lazy-fetched Go binary is blocked at launch with **Windows Defender event ID 1121** ("Microsoft Defender Exploit Guard has blocked an operation that is not allowed by your IT administrator") — a hard ASR *block*, not a SmartScreen/Gatekeeper warning. The rule is **`01443614-CD74-433A-B99E-2ECDC07BFC25`**, "Block executable files from running unless they meet a prevalence, age, or trusted list criterion." The lazy-fetched `enchiridion.exe` is unsigned and near-zero-prevalence, sitting in a user-writable cache path — exactly the profile the rule exists to stop. (Confirmed against the same machine: a signed, prevalent, IT-deployed `Joule Desktop.exe` runs fine from an equally user-writable `AppData\Local\Programs\` path — same rule, opposite verdict, because it clears the prevalence/trust criterion.)

Two facts, sourced from Microsoft Learn, close off the obvious "just sign it" and "just port the hot paths" escapes:

- **Signing is not a documented pass-condition for this rule.** Signing is documented as a pass-condition for the ransomware rule (`c1db55ab-…`), pointedly *not* for `01443614`. A code signature only slowly accrues cloud-delivered reputation; it does not deterministically clear this rule. So [#154](https://github.com/dhague/enchiridion/issues/154) (deferred code signing) would not reliably fix the block — it was never the fix.
- **The rule is PE-scoped** (`.exe`/`.dll`/`.scr`). Running the same logic as a `.js` payload under `node.exe` means the OS inspects `node.exe` — prevalent, signed, IT-approved — which passes; the `.js` is not a PE and is never the thing evaluated by this rule. The separate "block obfuscated/potentially-malicious scripts" ASR rule (`5beb7efe-…`) works through AMSI, and Node is not AMSI-integrated (AMSI is per-host opt-in; the documented integrated hosts are Microsoft scripting hosts — PowerShell, WSH, Office VBA — not Node). The same property — Node loads JS straight into V8 without calling the AppID/AMSI APIs — also puts node-run `.js` outside AppLocker/WDAC script enforcement. This is a reasoned negative from how the mechanisms are scoped, not a single quotable "Node is exempt" line, but it is high-confidence and now empirically backed.

**Empirically verified (2026-08-19):** a dependency-free `test.js` run natively (outside Joule Desktop's sandbox) from the exact blocked cache path — `…\.enchiridion-cache\v0.8.2` — on `node v26.7.0 win32 x64` executed cleanly: disk write+read, `WebAssembly.instantiate` of an inline module, and a `child_process` spawn all succeeded, with no new 1121 event. `WebAssembly.instantiate` mattered most: it is the mechanism `node-sqlite3-wasm` relies on, and it is the operation most likely to have tripped a rule. It did not.

## Why full port, not strangler

[ADR-0011](0011-go-rewrite-scope-sequencing-toolchain.md) migrated incrementally per subcommand, keeping the old implementation alongside the new until parity. That is impossible here: a locally-built Go `.exe` is *itself* an unsigned, near-zero-prevalence PE and trips the very same rule. Keeping Go for "the rest" would mean the rest does not run on Windows at all. So the port is all-or-nothing on Windows — the entire surface (~24 packages under `enchiridion-go/internal/`) must land in TypeScript, and the Go source is retired wholesale at parity rather than maintained in parallel (same "two implementations of every future feature is worse than one migration" reasoning ADR-0011 used to justify deleting the Python layer).

## Considered options

- **Sign the Go binary ([#154](https://github.com/dhague/enchiridion/issues/154)).** Rejected: not a documented pass-condition for rule `01443614`; buys only slow, uncertain cloud reputation, not a deterministic unblock.
- **IT allow-list (per-rule exclusion, file-hash IoC, or certificate IoC).** This *is* a deterministic non-JS fix — a certificate IoC in particular survives every future release, where a hash IoC needs re-adding per build. Rejected as the primary path because it requires an IT action in every environment the plugin lands in; it does not self-serve, and the plugin's reach is meant to be install-and-go.
- **Strangler (keep Go, port only the hot paths).** Rejected: see above — the local Go `.exe` is blocked too, so there is no partial-coverage story on Windows.
- **Full TypeScript rewrite on an approved interpreter.** Chosen. `node.exe` is the prevalent, trusted PE that satisfies the rule; our payload rides inside it as data.

## Toolchain

- **Language:** TypeScript, bundled by **esbuild** into a single `.js` plus the SQLite `.wasm` asset.
- **SQLite:** **`node-sqlite3-wasm`** — pure-WASM, FTS5 compiled in, real on-disk persistence, synchronous API mirroring Go's `ncruces/go-sqlite3`. Rejected `@sqlite.org/sqlite-wasm` (Node build is in-memory only) and `sql.js` (FTS3 only, no FTS5).
- **Git:** **`isomorphic-git`** (pure JS) — `readBlob`/`resolveRef({ref:'HEAD'})`/`walk({trees:[TREE({ref:'HEAD'})]})` cover [ADR-0015](0015-search-index-view-of-committed-history.md)'s read-content-from-HEAD-blobs requirement.
- **YAML:** **`eemeli/yaml`** — preserves key order and edits single scalars through the Document/AST model; the direct analogue of the Go port's `yaml.Node` approach for [ADR-0012](0012-go-frontmatter-round-trip-relaxed.md).
- **CLI / Markdown / property tests:** `commander` (or `yargs`), `remark`/`markdown-it`, `fast-check` (the `pgregory.net/rapid` analogue) — all pure JS.
- **Hard constraint — pure JS + WASM only, no native addons.** A native addon (a) reintroduces a PE/`.node` binary that re-trips the ASR rule this whole rewrite exists to clear, and (b) breaks Bun, OpenCode's runtime. This is why `node-sqlite3-wasm` is mandatory over `better-sqlite3`, and why any optional native path (e.g. `chokidar`'s `fsevents`) must degrade gracefully to pure JS.

## Distribution (retires [ADR-0013](0013-go-binary-lazy-fetch-dependency-free-bootstrap.md))

esbuild produces one bundled `.js` and the `.wasm` asset, shipped **inside the plugin** and — for Joule Desktop — as **skill supporting files under a `scripts/` subdirectory** (confirmed: Joule Desktop grants sandbox read+execute on installed skill directories at runtime, and its `skill-creator` documents the `scripts/` convention). There is **no runtime `npm install`, no registry, no network, no lazy fetch, no per-platform binaries, and no checksums/attestation/GoReleaser pipeline**. `wiki-plugin/bin/enchiridion` collapses to a thin `exec node <bundled.js> "$@"` shim (preferring `node` on `PATH`; the `ENCHIRIDION_BIN` dev override is retained). CI flips from GoReleaser's six-binary + Chocolatey + Homebrew + checksum matrix to a single esbuild bundle step.

## Consequences

- **The zero-runtime-dependency promise is gone.** Node (and Bun for OpenCode) becomes a stated prerequisite — the deliberate reversal of [ADR-0011](0011-go-rewrite-scope-sequencing-toolchain.md). This is accepted because the surviving driver (Claude Code on corporate-managed Windows under ASR, and inside Joule Desktop's sandbox) already has Node, and coding-harness users accept it. Hosts that lack Node — the pure non-coding-agent case ADR-0011 courted (Claude Desktop, Cowork) — must now install it; that regression is the price of clearing ASR, recorded honestly rather than papered over.
- **Dual-engine.** The bundle must run on Node (Claude Code, Joule Desktop) *and* Bun (OpenCode). CI runs the suite on both. **`node-sqlite3-wasm`-on-Bun is unverified and is the top technical risk** — a go/no-go spike before committing OpenCode support, not an assumption.
- **Code signing ([#154](https://github.com/dhague/enchiridion/issues/154)) becomes moot for the runtime artifact** — there is no own-built PE to sign — and the macOS quarantine remediation that [ADR-0013](0013-go-binary-lazy-fetch-dependency-free-bootstrap.md) carried is retired with the bootstrap.
- **[ADR-0012](0012-go-frontmatter-round-trip-relaxed.md) carries unchanged in spirit** — frontmatter round-trip stays non-byte-identical with key order preserved — but is now realised through `eemeli/yaml`, property-tested via `fast-check`. Likewise the move-touches-only-link-lines contract must be re-established and re-property-tested in TypeScript.
- **[ADR-0015](0015-search-index-view-of-committed-history.md) must be replicated with `isomorphic-git`**: the index stays a materialised view of `HEAD`'s `wiki/` tree read from git blobs, and the FTS5 schema (`SchemaVersion` `"4"`, `porter unicode61`, bm25 weights `0.0,10.0,5.0,1.0`) must match byte-for-byte so an index written by either implementation stays compatible across the transition — though full-port/no-strangler means far less cross-implementation overlap than ADR-0011 planned for.
