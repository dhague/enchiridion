# Go rewrite: full replacement, sequenced after OpenCode, pure-Go toolchain

> **Superseded by [ADR-0017](0017-typescript-rewrite-approved-interpreter-asr.md).** The Go binary is being replaced by a bundled TypeScript/JavaScript layer run on an already-installed interpreter (Node/Bun): the zero-runtime-dependency goal recorded below collided with Windows Defender ASR (event 1121, rule `01443614-…`), which blocks the unsigned, near-zero-prevalence own-built `.exe` and which signing does not reliably clear. The toolchain and distribution choices here are the ones ADR-0017 reverses; the "full replacement, no permanent parallel implementation" stance carries forward.

[#140](https://github.com/dhague/enchiridion/issues/140) rewrites the Python script layer as a single Go binary (`enchiridion`), distributed as a static executable per platform, so the plugin needs no Python (or any other runtime) installed — the blocker for using it from non-coding-agent hosts like Claude Desktop and Cowork. This is a full rewrite with eventual deletion of the Python scripts, not a permanent parallel implementation: maintaining two implementations of every future feature indefinitely was judged worse than the one-time migration cost.

The rewrite is sequenced **after** the OpenCode port ([#90](https://github.com/dhague/enchiridion/issues/90)–[#94](https://github.com/dhague/enchiridion/issues/94)) finishes, so it ports a single stable, feature-complete Python source of truth (covering both the Claude Code and OpenCode skill surfaces) rather than a moving target. It lands in a new top-level directory in this repo (e.g. `enchiridion-go/`), not a separate repository, consistent with this project's aversion to fragmenting documentation and history. Migration is **incremental per subcommand**, not big-bang: `search`/`init` ship first (read-only, lowest risk, validates the toolchain), then `ingest` (highest stakes — atomic multi-phase execution plus the two property-tested contracts, see [ADR-0012](0012-go-frontmatter-round-trip-relaxed.md)), then the remainder. Each skill/hook is updated to call the Go binary directly the moment its subcommand ships — no Python-fallback dispatch shim — so migration state stays visible file-by-file rather than hidden behind routing logic that would just be deleted later anyway. Because the shared `.wiki-knowledge/index.db` is written by whichever implementation a given skill currently calls, the `search`/`init` phase includes explicit cross-implementation compatibility tests (write with one driver, read with the other) rather than assuming SQLite's stable on-disk format guarantees FTS5 schema/tokenizer compatibility too.

Invocation shape is unchanged: skills and hooks still shell out via Bash to a CLI, just `enchiridion <subcommand>` instead of `python <script>.py`. This does not reopen [ADR-0001](0001-no-mcp-server.md).

## Toolchain choices

- **`ncruces/go-sqlite3`** (pure-Go, wasm-based) over `mattn/go-sqlite3` (cgo): cgo requires a C toolchain per target at cross-compile time — exactly the complexity a "download and run" binary exists to avoid, multiplied across six platform targets (macOS arm64+amd64, Linux amd64+arm64, Windows amd64+arm64). The pure-Go driver's one real constraint — single connection, no WAL — costs nothing extra here, since [ADR-0006](0006-stdlib-fts5-not-embeddings.md) already forbids WAL for this vault (Resilio Sync + SQLite sidecar files corrupts). FTS5 support comes via its separate `ext/fts5` package.
- **`go-git`**, embedded, rather than shelling out to a system `git` binary (the current `vault_git.py` approach): a hidden `git`-on-`PATH` dependency would undercut the whole point of the rewrite for the non-coding-agent hosts it targets.
- **`spf13/cobra`** for CLI/subcommand dispatch (build-time dependency only, doesn't affect the runtime zero-dependency goal), **`goldmark`** for CommonMark-compliant markdown parsing (`markdown-it-py`'s closest Go analog), **`pgregory.net/rapid`** for property-based tests (`hypothesis`'s closest Go analog, keeping [ADR-0005](0005-tdd-for-scripts-evals-for-agents.md)'s TDD-for-scripts contract meaningful in the new language).

## Consequences

Code signing/notarization for the distributed binaries is explicitly deferred, not silently dropped — it needs a paid Apple Developer account and a Windows code-signing certificate, a cost/process decision out of scope for the rewrite itself. Left unsigned, macOS Gatekeeper and Windows SmartScreen will warn or block on first run; the interim mitigation is that the bootstrap script detects the macOS quarantine-block case specifically and prints exact remediation rather than a generic error. Revisit signing if that mitigation proves insufficient in practice.
