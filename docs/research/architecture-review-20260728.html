Problem

The frontmatter schema has no module — it is re-encoded in _EDGE_KEYS, in KINDS, and twice in skill prose, so _index.md and a future search index can disagree about a page's tags.

Solution

Lift build_index._page_record into a PageRecord module — frontmatter text in, one typed record out, including derived kind and superseded_by. build_index becomes a renderer of records.

  • Locality: one place the schema changes
  • Leverage: one record, five callers
  • Interface is the test surface, not the table
  • Unblocks Vault.search() (#39)
  • Schema drift becomes impossible, not unlikely
  • Adds kind to code — today only prose has it
The research doc for #36 already names this: "Do share the extraction… This is the one code change that makes the whole thing coherent rather than parallel." This card is that change, standing on its own.

Problem

Solution

Enumeration becomes Vault's job alone. One pages() interface returning card A's records; move_page stops walking raw/ for markdown it will never rewrite.

  • One convention, zero rebasing bugs
  • Delete normalize_raw._load_wiki_pages
  • Locality: exclusions live in one module
  • Tests stub one interface, not four walks

Deep: the agent supplies judgment (kind, title, tags, edges, body); mechanics are absorbed and unit-tested.

Problem

The largest module in the plugin is 25 lines of prose, and it has no test surface. Its ordering constraints and the set-vs-merge footgun (a real bug caught by review in #15) are enforced only by an agent remembering.

Solution

Put the seam at a declared IngestPlan: pages with kind, title, frontmatter, body, edges. One ingest.py executes it and returns the commit SHA. Steps 1–3 (read, chunk, overlap) stay judgment; steps 4–9 stop being prose.

  • 12 shell calls become 1
  • set/merge choice moves into code
  • Ordering enforced, not remembered
  • Locality: partial-ingest failures in one module
  • Evals grade the plan, not the transcript
  • #21's per-chunk gap becomes a plan field
Touches ADR-0005. That ADR splits testing by layer — scripts get TDD, agents get evals. This moves the layer line, not the rule: mechanics cross into the TDD'd script layer and the eval'd agent layer shrinks to judgment. Worth confirming the intent, not reopening the ADR.

D. A link is a label and a destination

Worth exploring in-process

scripts/normalize_raw.py:38-81 · scripts/wikipage.py:54-66,148-183

Before — label knowledge leaks out

module
wikipage — link seam
LinkMatch models dest only; label is parsed then discarded
a second markdown parser, in a regex
module
normalize_raw._RAW_SOURCE_RE
(raw_source:\s*"\[)([^\]]*)(\]\()([^)]*)(\)")
re-finds the link wikipage just rewrote, to patch the half it wasn't told about

After — one splice carries both halves

deep module
LinkMatch(label, dest, spans)
plan_move(…, relabel=fn)
One back-to-front splice rewrites label and destination together. Byte-for-byte guarantee unchanged.
normalize_raw passes relabel=basename and loses its regex entirely.

Problem

raw_source's label must track a rename, but LinkMatch exposes only the destination — so a regex outside the link seam re-parses the document and patches the label after the fact.

Solution

Widen LinkMatch to carry the label span, and let a move optionally relabel. The link module stays the only markdown-link parser in the codebase.

  • One markdown-link parser, not two
  • Property tests already cover the splice
  • Leverage: relabelling any link, not just raw_source
Check #38 first. That open ticket proposes deleting normalize_raw.py outright (preserve raw filenames, percent-encode destinations). If #38 lands, this candidate mostly evaporates — the label span is still the right shape, but the leak it fixes is gone.

The seam is real: the same modules are also called in-process by tests and by card C's ingest.

Problem

Seven argparse adapters, each shallow, and wikipage.py takes a filesystem path for set but a vault-relative one for move — an interface wart the skills have to document around.

Solution

One wiki entry point dispatching subcommands, with vault-relative paths everywhere. The modules behind it don't move.

  • Skills document one interface
  • Path convention stops varying
  • Root resolved once, not per call
  • Smaller surface for a Haiku agent to learn

F. Split transcript capture at a pure seam

Speculative in-process

After — pure core, thin edge

Problem

The only script in scripts/ with no test file, because every decision in it is entangled with I/O and an import-time vault root. #33 wants to change the filename scheme with nothing to verify against.

Solution

Move filtering, rendering and naming behind one pure interface; leave main() as the adapter that reads the file and writes through Vault.

  • Restores ADR-0005's TDD rule here
  • #33 becomes a one-test change
  • Speaker labels stop being hardcoded

Top recommendation

It is the smallest change on the list and the one everything else waits on: Vault.search() (#39) will otherwise encode the schema a fifth time, card C's plan needs a record type to name, and B's pages() wants records to yield. Do it before #39 starts, not after.
